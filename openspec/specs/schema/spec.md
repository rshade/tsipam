# Schema Specification

## Purpose

Exposes a machine-readable catalog of every command, flag, and exit code
through `tsipam -schema`, generated by walking the live Cobra command
tree so it cannot drift from what the CLI actually accepts.

## Requirements

### Requirement: Schema catalogs every command and its local flags

`tsipam -schema` SHALL print a JSON document listing every available
command as its full dotted path (for example `site-id reserve`), each
command's summary and usage line, and that command's own non-persistent
flags. Every registry-backed command (`site-id`, `subnet`, and `service`
subcommands, plus `calc aggregate` and `calc next-free`) SHALL include `registry-dir` and `tailnet` in its flag list.
Root-level flags (`format`, `sanitize`, `schema`, `verbose`, `version`) SHALL
appear in the document's top-level flags list.

#### Scenario: Schema output lists the full command catalog

- **WHEN** an operator runs `tsipam -schema`
- **THEN** the JSON document's `commands` array includes `devices`,
  `devices list`, `site-id`, `site-id list`, `site-id reserve`,
  `site-id release`, `subnet`, `subnet list`, `subnet reserve`,
  `subnet release`, `subnet allocate`, `service`, `service list`,
  `service reserve`, `service release`, `calc`, `calc split`, and
  `calc info`

#### Scenario: Registry commands document their shared flags

- **WHEN** the schema document is inspected for any command whose name
  starts with `site-id`, `subnet`, or `service` followed by a subcommand
- **THEN** that command's flag list includes both `registry-dir` and
  `tailnet`

#### Scenario: Schema exposes registry aggregation

- **WHEN** the schema document is inspected for `calc aggregate`
- **THEN** it lists `from-registry`, `registry-dir`, and `tailnet`, and
  command help explains the mutually exclusive input sources

#### Scenario: Schema exposes subnet allocation

- **WHEN** the schema document is inspected for `subnet allocate`
- **THEN** it lists `size`, `owner`, `description`, `ticket`,
  `reserved-at`, `registry-dir`, and `tailnet`, `size` is marked required,
  and its usage line reads `subnet allocate <pool-cidr> <site-name>`

### Requirement: Schema documents exit codes and sanitization behavior

The schema document SHALL include exactly three exit-code entries (0, 1, 2)
with human-readable descriptions matching the tool's documented exit-code
scheme, and a `sanitization` field describing what `TAILSCALE_SANITIZE`
redacts. It SHALL distinguish exempt stateless calc output from sanitized
registry-derived aggregation and allocation-planning output.

#### Scenario: Exit codes are fully enumerated

- **WHEN** `tsipam -schema` runs
- **THEN** the `exit_codes` array contains one entry each for codes 0, 1, and
  2, with no duplicates and no gaps

### Requirement: Schema is unaffected by format or sanitize state

`-schema` SHALL ignore `--format` (it always emits JSON) and SHALL never
sanitize its own output, since it describes static tool capabilities rather
than tailnet-derived data. An invalid `--format` or `--sanitize` value
supplied alongside `-schema` SHALL still be rejected as a usage error before
the schema is printed.

#### Scenario: Valid sanitize flag alongside -schema stays silent

- **WHEN** an operator runs `tsipam -schema --sanitize identity`
- **THEN** the command exits 0, prints the schema document, and writes
  nothing to stderr (no sanitization-active notice, since -schema is never
  sanitized)

#### Scenario: Invalid format is rejected before the schema prints

- **WHEN** an operator runs `tsipam -schema --format bogus`
- **THEN** the command exits 2 and writes nothing to stdout

### Requirement: Both single- and double-dash spellings work for global flags

`-schema`/`--schema`, `-version`/`--version`, and `-help`/`--help` SHALL each
produce identical, pure-ASCII output regardless of dash count, matching Go's
conventional flag-parsing leniency.

#### Scenario: Single- and double-dash schema invocations agree

- **WHEN** `tsipam -schema` and `tsipam --schema` are both run
- **THEN** both exit 0 and print non-empty, ASCII-only stdout

### Requirement: Discover registry comparisons and drift semantics

The schema SHALL include `plan` and `check` with their `registry-dir` and
`tailnet` flags. Help and schema SHALL explain that check drift returns exit
1, collection failures return exit 2, and comparison identities are sanitized.
Both single- and double-dash long flags SHALL work for these commands.

#### Scenario: An agent discovers comparison commands

- **WHEN** `tsipam --schema` runs
- **THEN** the commands array includes plan and check with both registry selectors
- **AND** exit-code 1 describes check drift as well as existing refusals
